# layout-grid

- **Group by proximity: space within a group must be smaller than space between groups.** Related items and the labels that name them sit close, unrelated ones sit apart, and uniform spacing everywhere merges groups into clutter; a label equidistant between two fields gets read with the wrong one. Confidence: high. Sources: B88 p.224-227; B57 p.81-83; B20 p.758-759, 766-770; B27 p.148, 184-185; B44 p.97
- **Minimize the number of distinct alignment points.** Count elements plus every distinct column and row start; fewer alignment points predicted faster search and screens people liked more (one measured layout cut complexity about 31 percent and search time from about 8.3 s to 5.0 s). Align labels and controls to a shared grid and make near-equal widths and gaps exactly equal. Confidence: high. Sources: B46 p.178-182, 782; B26 p.444-447, 453; B35 p.260-261; B95 p.80, 203
- **Keep screen density low, ideally under about 30 percent.** Search time and errors rise sharply past roughly 29 percent character density; well-rated screens averaged about 14 to 15 percent, and reformatting crowded screens cut task time and errors by about a quarter. Confidence: high. Sources: B46 p.34-35, 210-212, 758, 784; B35 p.267-268
- **Keep repeated controls and items in the same place and order on every view.** People navigate by spatial memory, so a button that shifts between views slows frequent actions; add new items into empty space rather than reshuffling. Confidence: high. Sources: B86 p.40-41; B20 p.751-753; B92 p.44, 186-188; B88 p.236-237
- **Lay data out in labeled columns with whitespace.** The same records were searched in about 3.2 s when grouped into headed columns versus 5.5 s when packed with repeated labels on every row. Confidence: high. Sources: B02 p.130-131; B46 p.34
- **Build the layout on one spacing unit and one column grid.** Use a small atomic unit such as 4px and multiples of it for every gap, put modules on columns with fixed gutters, and never make a module narrower than one column. Confidence: medium. Sources: B26 p.445; B35 p.260-261; B10 p.54, 89, 93
- **Size margins, gutters, columns and modules as one proportional system.** Gutters and margins should relate to the column and module, ideally through a ratio (golden section about 1.618, rule of thirds, preferred-number series), not chosen in isolation. Confidence: medium. Sources: B10 p.18-35, 54, 89, 93; B92 p.62; B26 p.446-447
- **Derive vertical rhythm from the body leading.** Build the baseline grid and module heights from the body line height, choose heading and caption leadings that realign with the grid every few lines, and line up image edges with the x-height or baseline of the text. Confidence: medium. Sources: B88 p.238, 242-243; B10 p.102-105; B92 p.45
- **Let content choose the grid.** Settle the format from what the material is, then choose the grid type: column grids for running text, modular grids for many items of mixed importance, hierarchical grids for content that does not repeat. Confidence: medium. Sources: B92 p.17, 32, 40; B10 p.54, 88-92
- **Do not add more columns or modules than the content needs.** Fine grids such as twelve columns flex into 6+6, 4+4+4 or 3:6:3 but give less structure; coarse grids constrain but hold consistency, and too many tiny modules confuse. Confidence: medium. Sources: B92 p.48, 64; B10 p.54, 88-89, 92
- **Test every column span for a good measure.** A width that reads well in one column can fail when text spans two, so check every span and inner gutter of a multi-column grid. Confidence: medium. Sources: B92 p.28; B10 p.52, 89
- **Give each element only the width it needs.** A wide screen is not a reason to stretch a form or paragraph; split supporting text into a second column instead, and give sidebars a fixed width while the main content flexes. Confidence: medium. Sources: B47 p.76-81, 84-87
- **Leave room for translated text.** Paragraphs grow about 30 percent in translation, but labels under ten characters can grow 200 to 400 percent; use flexible containers and let layout managers reflow rather than hard-coding positions. Confidence: medium. Sources: B08 p.55-56, 74, 175
- **Use as few page templates as possible.** Repeating page types share one template so users learn the interface faster and global changes stay cheap; reserve bespoke layouts for a few pages such as home. Confidence: medium. Sources: B22 p.100-102; B38 p.51, 53; B62 p.92-93, 200-202
- **Put results next to the inputs that drive them.** Price, image and name belong in the buy button's group, and a chart driven by a calculator belongs beside it, not below the fold. Confidence: medium. Sources: B27 p.148, 184-185; B58 p.366, 368-369
- **Keep unrelated or dangerous controls apart.** Controls placed together are read as acting together, and look-alike switches side by side invite costly slips; split separate required settings into separate steps. Confidence: medium. Sources: B20 p.758-759, 766-770, 788
- **Set a hang line so each page begins at a consistent point.** A fixed horizontal datum where text or images start shows readers where to look after every page turn, and lets columns of unequal length hang from a common line. Confidence: medium. Sources: B92 p.28; B88 p.236-237
- **Overlay compatible grids with shared margins and flowlines.** A two-column grid over a three-column one, or separate grids for images and text, adds variety while the common anchors keep pages related. Confidence: medium. Sources: B92 p.46-47; B10 p.112-113
- **Treat the grid as an aid, not a law.** Break or relax it when content calls for it, but keep margins, markers and palette fixed so free layouts still cohere; chance-based layouts suit single posters, not long products. Confidence: medium. Sources: B10 p.75; B92 p.184, 186-188
- **Name page regions explicitly.** Header, body, sidebar, billboard and footer regions give engineers containers and give a component library a place rule for every component. Confidence: low. Sources: B62 p.92-93, 200-202
- **Keep primary content off tinted boxes.** Main content sits on the page background; boxes are for callouts, with at least 1em padding, and blocks of different hues need a gap of page background between them. Confidence: low. Sources: B59 p.9-11
- **Use a liquid width for results pages.** Letting result lists fill the available width shows more items per screen at every size. Confidence: low. Sources: B04 p.82-85
- **Give a narrow asymmetric column to captions and notes.** A narrow extra column next to equal text columns gives marginalia a home. Confidence: low. Sources: B10 p.97
- **Size side panels to the task and push content rather than cover it.** Page-local helpers belong in a side panel that shifts the page, deep work in a full page; large overlays that hide the parent page are the weakest choice. Confidence: low. Sources: B12 p.138-141
- **Place key content along the F-shaped scan.** Users scan across the top, then shorter lines below, then down the left edge; align key content with those fixations. Confidence: low. Sources: B06 p.166-168
- **Keep overlay controls at the edges in small AR views.** Corner buttons that open edge menus leave the center of the view clear. Confidence: low. Sources: B83 p.612
- **Design each page against its neighbors.** A strong page fails if it clashes with the facing or next page; let one page answer another. Confidence: low. Sources: B92 p.104
- **Check for tangents and accidental collisions.** Elements butting against each other or against a margin read as mistakes. Confidence: low. Sources: B95 p.80, 203
- **Balance visual weight around a central axis.** Treat color areas as weights on either side of the vertical axis; horizontals read calm, verticals lift and diagonals move into depth. Confidence: low. Sources: B70 p.91-92
- **Repeat shapes to signal relationships.** Repeated forms read as continuous and can group elements into larger balancing masses. Confidence: low. Sources: B71 p.108-110
